# 데일리 리포트 — 2026-07-21 (강민기)

## 오늘 한 일
- 음성 신고 파이프라인 안정화 작업을 진행했다. 신고 발생 시 피신고자 음성 파일을 라운드별 전원 자동 업로드 방식에서 온디맨드 업로드 방식으로 전환하고, 파일 업로드 완료까지 최대 5초 재시도 대기 로직을 구현했다.
- STT 로직을 개선했다. Azure Speech SDK 기반으로 전환하고, PCM 변환 실패 시 REST API로 fallback 유도, 취소 이벤트 핸들러 추가 및 에러 로그 상세화 등 안정성을 높였다. HITL 임계값도 confidence 0.7에서 0.9로 상향 조정했다.
- 이의 신청 API를 구현했다. DB 스키마에 `appeals` 테이블을 추가하고, 제출 시 관리자에게 실시간 알림(`notify_admins`)을 발송하도록 연결했다. 게임 클라이언트 측 최근 이의신청 조회 엔드포인트도 함께 추가했다.
- 웹소켓 예외 처리를 보강했다. `WebSocketDisconnect` 외 일반 예외도 catch하고, disconnect 후 브로드캐스트 실패를 무시하도록 수정해 런타임 오류를 줄였다. `recordings/` 디렉터리를 `.gitignore`에 추가하고, `game_start`·`request_voice_upload` 메시지 타입 중계 및 동시 게임 시작 동기화 흐름도 구현했다.

## 배운 점 / 특이사항
- 음성 파일 업로드 타이밍과 신고 처리 태스크 사이의 경쟁 조건(race condition)이 실제로 발생하여 재시도 대기 로직이 필요했다.
- STT 변환이 아직 완전히 성공 상태는 아니며 (`stt test` 커밋 기준 수정 중), 내일 품질 개선 작업에서 계속 검증이 필요하다.
- 음성 녹음 온디맨드 전환 결정을 `docs/decisions.md`에 기록했다.
