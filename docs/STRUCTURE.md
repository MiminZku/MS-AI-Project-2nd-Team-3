# 레포 구조 안내 — 뭐가 어디서 무슨 일을 하나

> 팀원용 요약: **여러분이 열어볼 곳은 `docs/`뿐입니다.**
> 매일 보는 건 `docs/daily-reports/`(내 리포트), 가끔 보는 건 `PROJECT.md`·`decisions.md`(방향 확인).
> 나머지는 기계 방이니 잊어도 됩니다.

```
팀레포/
├─ .github/workflows/    ⏰ 자동화 스케줄러 (GitHub이 읽음)
├─ scripts/              🤖 봇의 두뇌 (워크플로가 실행)
├─ docs/                 🧠 팀의 뇌 (사람 + AI가 읽고 씀)
├─ CLAUDE.md             📋 Claude Code에게 주는 규칙
└─ AGENTS.md             📋 Codex에게 주는 규칙 (내용 동일)
```

---

## `.github/workflows/` — "언제, 뭘 실행할지" 예약표

GitHub이 이 폴더를 감시하다가 정해진 시각에 스크립트를 대신 실행합니다. 파일 2개 = 자동화 2개.

| 파일 | 시각 (프로젝트 날 기준) | 하는 일 |
|---|---|---|
| `morning-briefing.yml` | 다음날 아침 9시 | Teams에 브리핑 2개 (어제 요약 / 오늘 제안 + 이탈 경고) |
| `daily-report.yml` | 밤 9시 | 팀원별 데일리 리포트 생성 → 레포에 커밋 + 기록 없는 사람 알림(리마인더 겸용) |

## `scripts/` — 실제 일하는 코드

워크플로가 시각이 되면 여기 있는 파이썬을 돌립니다. **팀원이 열어볼 일 없는 폴더.**

- `briefing.py` — 커밋 diff + ai-log 수집 → Claude API로 요약 → Teams 발송
- `daily_report.py` — 사람별 커밋·ai-log로 1인칭 리포트 작성 → daily-reports/에 저장

## `docs/` — 이 시스템의 심장, 팀의 공유 기억

| 파일/폴더 | 역할 | 누가 쓰나 |
|---|---|---|
| `PROJECT.md` | **헌법.** 만드는 것 / 안 만드는 것 / 확정 기술. 모든 AI가 세션 시작 때 제일 먼저 읽고, 이탈 감지의 기준 | 킥오프 때 팀이, 이후 결정 변경 시 갱신 |
| `decisions.md` | **결정 로그.** "언제 누가 왜 그렇게 정했나"가 한 줄씩 쌓임 | 주로 AI가 대화 중 자동 기록 |
| `plan.md` | **6일 로드맵.** 브리핑이 "오늘 Day 몇, 지연/정상" 판단하는 기준 | 킥오프 때 팀이 확정 |
| `team.md` | **역할표 + GitHub 아이디.** 브리핑의 담당자 지목, 리마인더의 사람 매칭 근거 | 킥오프 때 팀이 기입 |
| `rules/closing-rule.md` | AI용 매뉴얼: "마감해줘" 하면 뭘 할지 | 안 건드림 |
| `rules/report-format.md` | 데일리 리포트 양식. **과정 요구 양식이 있으면 여기에 교체** | 필요 시 팀장이 |
| `ai-log/` | "마감해줘" 하면 세션 요약이 `아이디-날짜.md`로 쌓이는 곳 | AI가 자동 |
| `daily-reports/` | 밤 9시마다 `날짜/이름.md`로 리포트 자동 생성. **아침에 자기 파일 열어 제출** | 봇이 자동 |

## `CLAUDE.md` / `AGENTS.md` — AI의 첫 지시문

Claude Code와 Codex가 **레포 폴더에서 켜지면 자동으로 읽는** 파일. "작업 전에 PROJECT.md 읽어라, 결정 바뀌면 기록해라, 마감 요청 오면 규칙대로 해라"가 적혀 있습니다. 이 파일 덕분에 6명의 AI가 같은 전제로 움직입니다.
