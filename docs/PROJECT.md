## 3. 파이프라인 아키텍처

```
[원본 문서] → ①수집/전처리 → ②청킹 → ③임베딩 → [벡터 저장소]
                                                      ↓
[사용자 질문] → ③임베딩 → ④검색(top-k) → ⑤생성(LLM+프롬프트) → [답변+근거]
                                                      ↓
                                              ⑥평가 (골든 QA셋)
```

### 모듈별 확정 결정

| # | 모듈 | 결정 항목 | 결정 | 상태 |
|---|---|---|---|---|
| ① | 데이터 | 대상 문서 (무엇을, 몇 건, 형식 pdf/html/md) | (미정) | `[결정]` |
| ① | 데이터 | 수집 방법 + **확보 실패 시 플랜 B** | (미정) | `[결정]` |
| ② | 청킹 | 전략 (고정 크기 / 문단 / 재귀), 크기·오버랩 | 예: 재귀분할 500자, 오버랩 50 | 미정 허용 |
| ③ | 임베딩 | 모델 (예: Azure `text-embedding-3-small`) | (미정) | `[결정]` |
| — | 저장소 | 벡터 DB (FAISS / Chroma / pgvector / Azure AI Search) | (미정) | `[결정]` |
| ④ | 검색 | top-k 값, 유사도 기준, 하이브리드 여부 | 예: k=5, 코사인, 하이브리드는 범위 밖 | 미정 허용 |
| ⑤ | 생성 | LLM (예: Azure `gpt-4o-mini`), 근거 인용 방식 | (미정) | `[결정]` |
| ⑤ | 생성 | 환각 방지 규칙 (근거에 없으면 "모른다"고 답하기) | 채택 | 확정 |
| ⑥ | 평가 | 골든 QA셋 규모(권장 20~30문항), 측정 지표 | (미정) | 미정 허용 |
| — | UI | 데모 화면 (Streamlit / Gradio 단일 페이지) | (미정) | 미정 허용 |

> 결정이 바뀌면: `decisions.md`에 한 줄 기록 + 이 표 갱신 (AI가 대신 해줌)

## 4. 인터페이스 계약 `[결정]` — 6명 병렬 작업의 생명줄

<!-- 모듈 담당자가 서로 달라도 조립이 되게, "주고받는 데이터의 모양"을 첫날 합의합니다.
     아래는 권장 기본값 — 킥오프에서 확인/수정 후 확정하세요. -->

**청크 파일** — ②청킹 출력 = ③임베딩 입력. `data/chunks.jsonl`, 한 줄에 하나:
```json
{"chunk_id": "doc03-012", "source": "문서명.pdf", "page": 4, "text": "...", "meta": {}}
```

**검색 함수** — ④검색 출력 = ⑤생성 입력:
```python
def retrieve(query: str, k: int = 5) -> list[dict]:
    """반환: [{"chunk_id", "text", "source", "page", "score"}, ...] score 내림차순"""
```

**답변 형식** — ⑤생성 출력 = UI·⑥평가 입력:
```json
{"answer": "...", "sources": [{"chunk_id": "...", "source": "...", "page": 4}]}
```

> 이 계약을 지키면 각자 모듈을 어떤 방식으로 구현하든 자유. **계약 변경은 반드시 decisions.md 기록 + 관련 담당자 합의.**

## 5. 보안 · 비용 규칙 (전원 필독, 위반 시 사고)

- **API 키는 절대 커밋 금지.** 키는 각자 로컬 `.env`에만 두고, 레포에는 `.env.example`(키 이름만)을 둔다. `.gitignore`에 `.env` 포함 확인.
- Azure OpenAI 쿼터/요금 한도를 첫날 확인하고, 배치 임베딩 등 대량 호출 전에는 예상 토큰량을 팀에 공유.
- 개인정보·저작권 문제가 있는 문서는 데이터셋에서 제외.
