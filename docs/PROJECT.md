## 1. 우리가 만드는 것 `[결정]`

**게임 이용자**가 부적절한 텍스트/음성 채팅을 **신고**하면, **시스템**이 Azure AI Speech(STT)로 음성을 텍스트화하고 Azure OpenAI(gpt-5-mini)가 RAG 규정 지침 DB를 조회해 제재 수위를 판정한 뒤, 근거(우편 내용)와 함께 조치를 반환하는 **신고 기반 게임 채팅·음성 제재 시스템**.

### 데모 시나리오 (타운홀에서 보여줄 장면)

1. 유저가 부적절한 채팅/음성을 신고하면 (음성은 .wav로 전송)
2. Azure AI Speech가 음성을 텍스트로 변환하고, 게임 서버가 신고 텍스트를 Azure OpenAI(gpt-5-mini)로 전송하면
3. gpt-5-mini가 RAG 규정 지침 DB를 조회해 제재 수위 + 우편(안내) 내용을 판정하고, 저신뢰 케이스는 관리자 대시보드로 HITL 검토를 보낸다

> 매일의 우선순위 판단 기준: **"이 작업이 데모 시나리오(신고 → STT → gpt-5-mini 판정 → 조치)에 필요한가?"**

## 2. 우리가 만들지 않는 것 `[결정]` — 방향 이탈 방지의 핵심

- **신고 없는 전수 상시 모니터링.** 모든 채팅/음성을 감시하는 구조는 채택하지 않는다. 유저의 신고가 있어야 분석이 시작된다 — 이전 초안의 "선제적 감지" 문구는 폐기.
- **별도 로컬 분류기(KcELECTRA) 또는 Azure Content Safety 1차 필터 추가.** 판단은 Azure OpenAI(gpt-5-mini) 단일 엔진 + RAG 정책 조회로 통합한다. 이 구조를 다시 하이브리드로 되돌리는 논의가 나오면 브리핑이 경고하도록 둔다.
- **korcen 등 규칙 기반 라이브러리 단독 사용.** 변형 욕설 탐지 실패가 검증되어 기각된 방식.
- 로그인/회원가입 등 사용자 계정 관리 (게임 자체 시스템에 위임)
- 한국어 외 다국어 지원
- 클라우드 프로덕션 배포 (데모는 로컬/개발 서버 기준)
- (팀에서 추가)

**재확인 필요 (이전엔 확정이었으나 새 아키텍처와 충돌 가능):**
- 영구정지의 모델 자동 판단 금지 원칙 — gpt-5-mini가 제재 수위를 전부 판단하는 구조에서 이 원칙이 여전히 유효한지 (예: 영구정지는 gpt-5-mini 출력 범위에서 제외하고 수동 트랙으로 분리하는지) 팀 확인 필요.
- 재범 가중을 DB count 쿼리로만 처리하고 ML/LLM은 배제한다는 원칙 — 다이어그램상 별도 카운트 모듈이 안 보이므로, gpt-5-mini가 재범도 함께 판단하는지 확인 필요.

## 3. 파이프라인 아키텍처

```
[게임 클라이언트] --신고요청(음성/채팅)--> [게임 서버] --신고음성(.wav)--> Azure AI Speech(STT)
                                                  <--변환 텍스트 반환--
[게임 서버] --분석용 텍스트 전송--> Azure OpenAI(gpt-5-mini) <--지침 조회/반환--> RAG 규정 지침 DB
[게임 서버] <--제재 수위 + 우편 내용 반환-- Azure OpenAI(gpt-5-mini)
Azure OpenAI(gpt-5-mini) --저신뢰 케이스(HITL)--> [관리자 대시보드]
[게임 서버] --제재 조치(채팅금지/킥)--> [게임 클라이언트]
[게임 서버] --제재기록/음성파일 저장--> [로컬 DB(PostgreSQL) & 저장소]
[게임 클라이언트] --오탐 신고(이의제기)--> [관리자 대시보드] --제재 승인/해제 명령--> [게임 서버]
```

### 모듈별 확정 결정

| 영역 | 결정 항목 | 결정 | 상태 |
|---|---|---|---|
| 입력 | 트리거 방식 | 유저 신고(텍스트/음성) 기반 | 확정 |
| 입력 | 음성 STT | Azure AI Speech | 확정 |
| 판단 | 판단 엔진 | Azure OpenAI gpt-5-mini 단일 엔진 (KcELECTRA·Content Safety 미사용) | 확정 |
| 판단 | 정책 근거 | RAG 규정 지침 DB | 확정 |
| 판단 | 임베딩 모델 · 벡터 저장소 | (미정) | `[결정]` |
| 판단 | HITL 임계값 | 저신뢰 케이스 → 관리자 대시보드 (구체 수치 미정) | `[결정]` |
| 제재 | 조치 실행 | 게임 서버가 채팅금지/킥 직접 집행 | 확정 |
| 제재 | 승인/해제 | 관리자 대시보드 수동 명령 | 확정 |
| 제재 | 레벨 체계·재범 가중·영구정지 원칙 | 기존 Lv.0~4 체계가 새 구조에서도 유효한지 | 재확인 필요 |
| 이의제기 | 오탐 신고 | 유저 → 관리자 대시보드 | 확정 |
| 저장 | 로컬 DB | PostgreSQL (제재기록 + 음성파일) | 확정 |
| 대시보드 | 프론트엔드 프레임워크 | (미정, 이전 React 가정) | `[결정]` |

> 결정이 바뀌면: `decisions.md`에 한 줄 기록 + 이 표 갱신 (AI가 대신 해줌)

## 4. 인터페이스 계약 `[결정]` — 6명 병렬 작업의 생명줄

**신고 이벤트** — 클라이언트 출력 = 게임서버 입력:
```json
{"report_id": "...", "reporter_id": "...", "target_user_id": "...", "channel": "text|voice", "content": "text or audio_ref(.wav)", "timestamp": "..."}
```

**STT 결과** — Azure AI Speech 출력 = 판단 엔진 입력:
```json
{"report_id": "...", "transcribed_text": "..."}
```

**판단 결과** — Azure OpenAI 출력 = 게임서버·대시보드 입력:
```json
{"report_id": "...", "sanction_level": 0, "mail_content": "...", "confidence": 0.0, "needs_human_review": false}
```

**대시보드 명령** — 관리자 대시보드 출력 = 게임서버 입력:
```json
{"report_id": "...", "action": "approve|release", "reviewer_id": "..."}
```

> 이 계약을 지키면 각자 모듈을 어떤 방식으로 구현하든 자유. **계약 변경은 반드시 decisions.md 기록 + 관련 담당자 합의.**

## 5. 보안 · 비용 · 개인정보 규칙 (전원 필독, 위반 시 사고)

- **API 키는 절대 커밋 금지.** 각자 로컬 `.env`, 레포에는 `.env.example`만. `.gitignore`에 `.env` 포함 확인.
- Azure AI Speech / OpenAI 쿼터·요금 한도를 확인하고, 대량 호출 전 예상 호출량을 팀에 공유. (Content Safety/KcELECTRA로 분산되던 1차 필터가 없어졌으므로 모든 신고가 gpt-5-mini 호출로 직결됨 — 비용·쿼터 여유를 특히 신경 쓸 것)
- **신고 음성 파일·채팅 원문은 개인정보로 취급.** 저장 시 접근 권한을 관리자 대시보드 인증 사용자로 제한.
- **허위/악의적 신고 남용 방지 정책** 수립 필요 — 오탐 신고(이의제기) 경로가 있으니 남용 패턴 모니터링 고려.

## 6. 리스크와 사전 대응

| 리스크 | 징후 | 대응 |
|---|---|---|
| gpt-5-mini 단일 엔진 장애/지연 시 전체 파이프라인 정지 | 판단 응답 지연, 429 에러 | 재시도 로직 + 응답 캐싱, 폴백 메시지 정의 |
| 1차 필터 없이 전량 LLM 호출 → 비용/쿼터 초과 | 신고량 급증 시 API 한도 근접 | 신고 rate limit, 쿼터 대시보드 모니터링 |
| 허위/악의적 신고 남용 | 특정 유저 대상 신고 폭주 | 신고 빈도 제한, 오탐 신고 통계로 패턴 탐지 |
| RAG 규정 지침 DB 품질 저조 | 판단 근거가 정책과 안 맞음 | 골든 케이스로 검색 품질 스모크 테스트 |
| **팀 내 아키텍처 재논쟁** (다시 하이브리드로 회귀 시도 등) | 데일리 리포트/커밋에 KcELECTRA·Content Safety 재도입 시도가 감지됨 | 브리핑 ⚠️ 즉시 경고 → 2번 섹션 재확인 |
| 개인정보/법적 리스크 | 신고 음성·채팅 원문 노출 | 접근권한 제한, 저장 기간 정책 수립 |
| 범위 폭발 | "이것도 넣자"가 반복 | 2번 섹션 참조 → 브리핑 ⚠️ → 그날 중 정리 |
