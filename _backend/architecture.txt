💻 [로컬 환경] 사과게임 통합 아키텍처 및 AI 제재 파이프라인
모든 서버와 프론트엔드는 질문자님의 PC 안에서 각각 다른 포트(Port)를 열고 실행됩니다. 복잡한 클라우드 세팅이나 Redis 통신 없이, 서버 메모리(RAM)와 내 하드디스크를 직접 활용합니다.

1. 프론트엔드 계층 (로컬 개발 서버)
클라우드 호스팅(SWA) 대신, 로컬에서 Node.js 개발 서버를 띄워 접속합니다.

게임 클라이언트 (localhost:3000):

유저가 브라우저로 접속해 사과게임을 플레이하고 채팅/음성을 주고받는 화면.

금칙어 사전 기반의 1차 마스킹 처리 적용.

이의신청 폼(/appeal) 포함.

어드민 대시보드 (localhost:3001):

CS 운영자가 접속하는 관리자 화면.

[신규 추가] AI가 차단(콘텐츠 필터)하여 판단을 포기한 '수위 높은 악성 데이터'가 최우선 대기열로 올라오는 UI 추가.

2. 백엔드 계층 (단일 로컬 서버)
복잡한 컨테이너(ACA)와 Redis(메시지 브로커)를 완전히 걷어냈습니다. FastAPI 서버 1대 (localhost:8000)가 모든 역할을 통짜(Monolithic)로 수행합니다.

메모리 공유 (웹소켓 제어): 서버가 1대이므로, 접속한 유저들의 WebSocket 연결 객체를 파이썬의 Dictionary(사전) 형태로 메모리에 들고 있습니다. AI 판정(혹은 인간 판정)이 내려지면 딕셔너리에서 해당 유저를 찾아 즉시 연결을 끊습니다. (Redis 불필요)

로컬 파일 시스템 활용: Blob Storage 대신 프로젝트 폴더 내부에 /uploads/temp-voice, /uploads/appeals 같은 폴더를 만들어 음성(.wav)과 이미지(.png)를 직접 저장하고 삭제합니다.

3. 데이터 저장소 계층 (로컬 DB)
DB: 클라우드 DB 대신 로컬 PC에 직접 설치한 PostgreSQL (또는 테스트가 더 편한 SQLite)를 사용합니다.

테이블 구조(users, reports, sanction_history, appeals)는 기존과 동일하게 유지합니다.

4. 외부 AI API 호출 계층 (인터넷 통신)
로컬 서버에서 코드 실행 중, 분석이 필요할 때만 외부 클라우드의 AI API를 호출해서 결과만 받아옵니다.

Azure AI Speech: 로컬에 저장된 음성 파일을 API로 쏴서 텍스트로 받아옵니다.

Azure OpenAI (gpt-4o-mini): 최종 판단을 요청합니다.

🚨 [핵심 업데이트] 콘텐츠 필터 예외 처리 및 CS 이관 흐름
질문자님이 기획하신 "수위가 너무 높아 AI가 뱉어버린 데이터를 사람에게 넘기는 로직"은 백엔드 코드에서 아래와 같이 작동하게 됩니다.

AI 심사 요청: FastAPI 서버가 OpenAI API로 프롬프트를 전송합니다.

필터 차단 발생: OpenAI가 입력을 거부하고 400 Bad Request (Content Filter Flagged) 에러를 뱉어냅니다.

예외 처리 (Try-Except): 백엔드가 서버 다운을 막고 이 에러를 Catch 합니다.

DB 상태 변경: 해당 신고 건의 DB status를 AI_REJECTED 또는 MANUAL_REVIEW_REQUIRED로 업데이트합니다.

어드민 대시보드 노출: CS 관리자가 localhost:3001 대시보드를 새로고침하면, "⚠️ AI 판단 불가 (수위 초과) - 수동 심사 요망"이라는 붉은색 뱃지가 달린 티켓이 최상단에 뜹니다.

인간의 철퇴 (Kick): 관리자가 원본 로그를 눈으로 확인하고 [수동 강제 30일 정지] 버튼을 누르면, FastAPI가 메모리에서 유저의 소켓을 찾아 연결을 끊어버립니다.
