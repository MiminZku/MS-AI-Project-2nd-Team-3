# AI PM 시스템 — 기술 설명 (A to Z)

## 0. 한 문장 요약

우리가 매일 하는 개발 활동(커밋, AI 대화)을 **GitHub이 읽어서 → AI가 요약·판단하고 → Teams로 보내주는** 자동 파이프라인입니다. 사람이 추가로 하는 일은 거의 없습니다.

---

## 1. 큰 그림 — 3개의 축이 엮여 있다

```
[GitHub 레포]  ←→  [AI: Claude/Codex]  →  [Teams]
   팀의 기억           읽고 쓰는 주체          알림 창구
```

- **GitHub 레포** = 모든 것이 저장되는 중심. 코드 + 문서 + 팀의 결정이 다 여기 모입니다.
- **AI (Claude Code / Codex)** = 레포를 읽고, 요약하고, 파일을 쓰는 실제 일꾼.
- **Teams** = 결과물이 도착하는 곳. 우리는 여기서 확인만 합니다.

핵심 설계 원칙: **"사람은 개발만, 나머지는 자동."** 컨텍스트 관리·진행 취합·리포트 작성을 사람이 안 하게 만드는 게 목표입니다.

---

## 2. GitHub 레포 구조 — 무엇이 어디에

```
레포/
├─ .github/workflows/   자동화 예약표 (GitHub이 정해진 시각에 실행)
├─ scripts/             실제 도는 파이썬 코드
├─ docs/                팀의 기억 (문서 전부)
├─ CLAUDE.md / AGENTS.md  AI가 시작할 때 읽는 규칙
```

`docs/` 안이 이 시스템의 심장입니다:

| 파일 | 역할 |
|---|---|
| `PROJECT.md` | 프로젝트 헌법 — 만드는 것/안 만드는 것/확정 기술. **모든 판단의 기준** |
| `decisions.md` | 결정 로그 — 언제 뭘 왜 정했나 |
| `plan.md` | 6일 로드맵 — 오늘이 Day 몇인지 |
| `team.md` | 역할표 + GitHub 아이디 |
| `ai-log/` | "마감해줘" 세션 요약이 쌓이는 곳 |
| `daily-reports/` | 데일리 리포트가 쌓이는 곳 |

---

## 3. 어떻게 AI가 "우리 프로젝트"를 아는가 — 컨텍스트 주입

가장 중요한 기술적 트릭입니다.

Claude Code는 실행되면 폴더의 **`CLAUDE.md`를 자동으로 읽습니다.** Codex는 **`AGENTS.md`**를 읽고요. 이 파일에 우리가 이렇게 적어놨습니다:

> "작업 시작 전 반드시 `docs/PROJECT.md`와 `docs/decisions.md`를 읽어라."

그래서 팀원 누가 AI를 켜든 → AI가 프로젝트 방향과 최근 결정을 먼저 읽고 시작합니다. **6명의 AI가 전부 같은 전제에서 출발**하는 거죠. 이게 "컨텍스트 동기화"의 핵심 원리입니다.

추가로 규칙 하나 더:

> "대화 중 기술 결정이 바뀌면 `decisions.md`에 한 줄 기록해라."

그래서 결정이 생기면 **AI가 스스로** 로그를 남깁니다. 사람이 회의록 쓸 필요가 없어요.

## 4. 아침 브리핑 — 어떻게 만들어지나

**트리거:** `.github/workflows/morning-briefing.yml`
GitHub Actions의 크론(cron) 스케줄로 정해진 날 아침 9시(KST)에 자동 실행됩니다.

> 참고: 크론은 UTC 기준이라 `0 0` = 한국시간 9시. 실행 날짜도 우리 프로젝트 일정(7/16, 20~24)에 맞춰 고정해뒀습니다.

**동작 순서 (`scripts/briefing.py`):**

1. `git log --all`로 **모든 브랜치**의 지난 커밋과 diff를 수집
   - → feature 브랜치에만 push해도 잡힙니다. main merge 안 해도 OK.
2. `docs/ai-log/`에서 어제 마감 요약을 수집
3. 이 둘 + PROJECT.md + plan.md + team.md를 묶어서 **Claude API에 전송**
4. AI가 두 개의 메시지를 생성:
   - **브리핑 1** — 어제 한 일 (팀원별 요약 + 새 결정 + 활동 없는 사람)
   - **브리핑 2** — 오늘 할 일 (plan.md 대비 진행상황 + 담당별 제안 + ⚠️ 이탈 경고)
5. Teams 웹훅으로 카드 2장 발송

**이탈 감지 원리:** 어제 커밋 diff를 PROJECT.md의 확정 결정과 비교해서, 어긋나는 게 보이면 ⚠️로 표시합니다. (예: 결정은 FAISS인데 ChromaDB 코드가 올라옴)

---

## 5. "마감해줘" — 어떻게 작동하나

**트리거:** 팀원이 AI 채팅창에 "마감해줘" 입력 (수동, 선택)

**동작 (`docs/rules/closing-rule.md`에 적힌 절차대로 AI가 실행):**

1. 오늘 세션 대화를 5줄로 요약
2. `docs/ai-log/<아이디>-<날짜>.md`로 저장
3. `git pull --rebase` 후 커밋 + push

**중요한 특성:**
- 매일 / 각자 / 수동입니다. 치면 생기고, 안 치면 그날은 없습니다.
- push가 이 안에 포함됩니다. → **마감해줘를 하면 push를 따로 안 해도 됩니다.**
- 코드가 없는 날(조사·설계만 한 날)에 특히 유용 — 커밋만으론 안 보이는 활동을 남기니까요.
- 단, AI가 **레포 폴더 안에서 돌 때만** 작동합니다.

## 6. 데일리 리포트 — 어떻게 만들어지나

**트리거:** `.github/workflows/daily-report.yml`
**수동 실행**입니다. 전재희가 Actions 탭에서 "Run workflow" 버튼을 누릅니다.

**동작 (`scripts/daily_report.py`):**

1. `team.md`에서 팀원 목록을 읽음
2. 사람별로 오늘의 커밋 + ai-log를 수집
3. 각자의 자료를 Claude API에 보내 **1인칭 리포트** 생성
   - 형식은 `docs/rules/report-format.md`를 따름 (과정 양식이 있으면 여기 교체)
   - 자료에 없는 내용은 지어내지 않음 (커밋·ai-log 둘 다 없는 사람은 건너뜀)
4. `docs/daily-reports/<날짜>/<이름>.md`로 저장하고 커밋
5. Teams에 완료/미제출 알림 + 그날 리포트 폴더로 가는 링크 발송

리포트는 봇이 초안을 쓰고, **각자 아침에 자기 것 검토 후 제출**하는 방식입니다.

## 7. 하루 데이터 흐름 (전체 통합)

```
[아침] 각자 git pull → AI 열기 (PROJECT/decisions 자동 로딩)
   ↓
[낮] 개발 + AI 대화 → 결정 나면 AI가 decisions.md 기록
   ↓
[저녁] feature 브랜치에 push  /  또는 "마감해줘"(요약+push 한번에)
   ↓
[밤] 전재희가 리포트 버튼 → 봇이 사람별 리포트 생성 → Teams 알림
   ↓
[다음날 9시] Actions 자동 실행 → 브리핑 2장 → Teams
```

사람이 실제로 하는 것: **pull, 개발, push(또는 마감해줘)** — 그리고 전재희의 리포트 버튼 한 번. 나머지 화살표는 전부 자동입니다.

---

## 8. 브랜치 전략

- 자동화 파일은 처음 **main에 직접** 커밋 (Actions는 main 것만 실행하므로)
- 팀원 작업은 `feature/이름` 브랜치 → push → PR → 리뷰 1명 → main merge
- **코드는 PR, 문서(ai-log·리포트)는 바로** — 문서는 충돌 없으니 PR 안 태움
- 브리핑은 전 브랜치를 읽으므로 merge 전에도 진행상황이 다 보임

---

## 9. 최초 세팅 (전재희가 1회)

1. 키트 전체를 레포 main에 커밋
2. Teams 채널(게시물 모드) + Workflows 웹훅 URL 발급
3. GitHub Secrets에 2개 등록: `ANTHROPIC_API_KEY`, `TEAMS_WEBHOOK_URL`
4. `PROJECT.md` / `team.md` / `plan.md` 채우기
5. Actions에서 morning-briefing 수동 실행 → 작동 테스트

## 10. 알아둘 한계 (정직하게)

- **API 비용**: Claude API 사용 — 하루 몇 백 원 수준, 6일 총 $1 미만
